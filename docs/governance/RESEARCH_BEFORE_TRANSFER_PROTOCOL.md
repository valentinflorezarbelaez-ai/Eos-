## 1. The Core Principle: Anti-Dogmatic Intelligence

> [!IMPORTANT]
> **MANDATE:** EOS must never blindly apply an internal BKM simply because it exists in memory.
> When encountering a new or adjacent domain, EOS must execute an empirical **Context Similarity & Ecosystem Gap Analysis** before deciding whether to transfer, adapt, research, or reject the pattern.

```text
PROPOSED DOMAIN / TASK
          │
          ▼
   1. CONTEXT SIMILARITY ANALYSIS
      (Evaluate structural, data, latency, and threat profile overlap)
          │
          ▼
   2. ECOSYSTEM RESEARCH & BENCHMARK
      (Search existing skills, MCPs, native web APIs, and industry solutions)
          │
          ▼
   3. TRANSFER POLICY DECISION GATE:
      ├── Similarity >= 0.85 & Low Drift   ──► [TRANSFER]
      ├── Similarity 0.60 - 0.84           ──► [RESTRICTED_TRANSFER (with sandbox)]
      ├── Similarity 0.30 - 0.59           ──► [RESEARCH_FIRST]
      └── Negative Threat / Counter-Ind.   ──► [DO_NOT_TRANSFER]
```

---

## 2. Decision Policy Taxonomy

1. **`TRANSFER`**: Domain is within verified `VALID_SCOPE`. Direct application authorized with standard TDD.
2. **`RESTRICTED_TRANSFER`**: Domain is in `PROBABLE_SCOPE`. Requires pre-registered prediction, frozen hypothesis, and sandbox trial.
3. **`RESEARCH_FIRST`**: Domain has uncharacterized constraints. Requires exploratory benchmarking before constructing an implementation plan.
4. **`DO_NOT_TRANSFER`**: Domain presents counter-indicated characteristics (e.g. streaming binary buffers vs. DOM regex). Requires formal recording in [`docs/knowledge/NEGATIVE_BKM_CATALOG.json`](file:///c:/Users/valen/Documents/Eos%20system/docs/knowledge/NEGATIVE_BKM_CATALOG.json).
