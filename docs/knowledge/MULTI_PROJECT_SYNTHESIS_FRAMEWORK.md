## 2. Higher-Order Engineering Synthesis (Cross-Domain Abstraction)

Synthesizing these 3 distinct project experiences yields 4 unified EOS Engineering Principles:

### Principle 1: Universal Viewport Information Architecture (`LSN-001` Synthesis)
> *"Layout structures must not merely collapse menus; data density (tables, forms, grids) must dynamically transform into cards or touch-optimized components below < 640px from Day 1."*

### Principle 2: Strict Boundary Contract & Failure Visibility (`SYS-PRN-001` Synthesis)
> *"Data crossing any system boundary (Form -> External URL, Form -> API, API -> DB) must enforce strict schema contracts at the entry boundary and yield deterministic, observable error states (e.g. 400 Bad Request, 409 Conflict) rather than silent data degradation."*

### Principle 3: Data Privacy & Minimization by Design (Sonrisa Synthesis)
> *"Interactions soliciting user or biomedical data must minimize input fields to strictly necessary attributes, enforce explicit consent prior to transmission, and avoid unencrypted third-party persistence."*

### Principle 4: Native Runtime Capability Discovery (`ENV-001` Synthesis)
> *"Before adding external dependencies or native C++ add-ons, the execution environment must be probed for native runtime primitives (e.g. `node:sqlite`, `node:crypto`), reducing build complexity and toolchain dependencies."*
